# 第5段階：受付での作業先の確定（実行前の確認まで）

## 範囲

2026-11-12に固定したgoal charter（`target/swarm-run-stage5/charter.md`）による。
Rustネイティブ受付（`h2o-native`）で、作業ディレクトリを入力せずに受付を開いたまま、利用者が作業先フォルダと権限を明示的に選び、検証して確定できるようにする。
確定すると作業セッションの計画（どのフォルダ・どの権限で作るか）がデータとして得られるが、作業セッションは作らない。
受付のチャットは従来どおり、ツール無効・自動承認なし・中立の空フォルダで作るセッションのまま変えない。

範囲外：実際の作業セッションの開始、daemon・provider・Jev・ネットワークへの呼出、ツールの有効化、パスの候補表示・補完・プロジェクト探索、確定した作業先の再起動後の保持、bot登録、SemEvolve、H₂Oメモリの変更。

## 契約

### 作業先の状態（`src/work_target.rs`、eguiにもSDKにも依存しない）

- 状態は 未確認 → 確認待ち → 確定済み。入力が空白だけで権限も未選択なら未確認、どちらかがあれば確認待ち、検証済みの正規化パスを持つときだけ確定済み。
- パスは利用者の入力だけから取る。環境変数・ユーザー名・ホーム・カレントディレクトリ・スナップショットから推測しない。空の入力と相対パスは拒否する（相対パスはカレントディレクトリ基準の解決になるため、`作業先は絶対パスで入力してください`）。
- 確定の前に、存在する・フォルダである・読み取れることを確認し、正規化（`fs::canonicalize`）した値を確定値とする。見つからない／フォルダではない／読み取れないを別の文言で返す。入力されたパスのフォルダを作らない。
- 権限は `読み取り専用` か `読み書き` を明示的に選ぶ。既定値はなく、選ぶまで確定できない。
- 確定後にパスか権限を別の値へ変えると、確定は外れて確認待ちに戻る。同じ値を入れ直しても確定は保つ（画面からの毎フレームの書き戻しのため）。
- 計画（`WorkSessionPlan`：正規化した作業フォルダと権限）は確定済みのときだけ得られる。計画の取得時にフォルダを確認し直し、なくなっていれば確定を外してエラーを返す。計画はデータだけで、作業セッション・SDK・daemonには触れない。

### 受付の画面（`src/native_ui.rs`）

- 監視ペイン（幅1180pt以上は右列、760pt以上は見出しの「監視パネル」、それ未満は「監視」タブ）の「状態」の下に「作業先」欄を置く。絶対パスの入力欄、`読み取り専用`／`読み書き` の選択（最初はどちらも未選択）、`確定` ボタン、エラー行。
- `確定` は、パスが空でなく権限を選んだときだけ押せる。押すと検証と計画の作成だけを行う。
- 状態行は `作業対象: 未確認`／`作業対象: 確認待ち`／`作業対象: 確定済み: <パス> · <権限>`。由来は「事実」（検証した内容だけを示す）。1行で、幅に収まらない分は省略記号（…）で切る（表示セル数で数える既存の `row`／`line` の切詰めをそのまま使う）。
- 確定すると、由来「計画」の行 `計画（未実行）: <権限>の作業セッション · <パス>` を出す。実行中ではないことを表す。
- 別の行 `チャット: ツール無効・自動承認なし（作業対象を確定しても編集・実行しません）` を常に出す。見出しの帯（デモ・実会話の両方）も `チャットは編集・実行しません` を状態より前に置き、幅が足りなくても制限の文言が先に切れないようにした。
- Windowsの正規化パスは `\\?\D:\…`（UNCは `\\?\UNC\server\share`）になる。表示のときだけこの接頭辞を外す（`native::display_path`）。保持する確定値は正規化したまま。
- 入力の前後の空白と、Windowsの「パスのコピー」で付く `"` は画面側で外してから渡す（エンドポイント欄・取込欄と同じ扱い）。
- デモ応答の文言を「作業対象が未確認のため」から「このチャットではファイルの編集や実行は行いません（作業対象を確定しても同じです）」へ変えた。確定後も真であるため。

### チャットは変えない

確定した作業先はチャットのコントローラ（`chat_transport`）へ渡さない。チャットのセッションは従来どおり、中立の空フォルダ（一時ディレクトリの `h2o-native-chat` 配下）、固定のsystem prompt（`CHAT_SYSTEM_PROMPT`）、空のツール集合、`supports_user_response: false` で作り、権限要求は拒否する。`chat_transport.rs` は変更していない。

## 試験

Git Bashでリポジトリのルートから（PowerShellの `$env:RUSTC_WRAPPER=''` はbuildを壊す）:

```bash
export RUSTC_WRAPPER=
cargo test --offline --locked --manifest-path experiments/h2o-drift/Cargo.toml --target-dir target/h2o-native --features "native-ui jev"
cargo test --offline --locked --manifest-path experiments/h2o-drift/Cargo.toml --target-dir target/h2o-native
```

結果（2026-11-12、Windows 11）:

| features | passed | failed | ignored | exit |
|---|---|---|---|---|
| `"native-ui jev"` | 184 | 0 | 5 | 0 |
| なし | 38 | 0 | 3 | 0 |

warningは0件。第4段階の終了時（167件、ignored 5）から、`work_target` の単体試験14件と画面・チャットの試験3件を加えた。featureなしの38件には `work_target` の14件が含まれ、この部品がeguiにもSDKにも依存しないことを示す。

追加した試験：

- `src/work_target.rs`（14件）：空・空白、相対パス、存在しないパス（フォルダを作らない）、ファイル、正規化（`sub/..`・`.`・前後の空白）、権限の既定なし、パス変更・権限変更で確定が外れる、同じ値では外れない、未確定・確認待ちでは計画を拒否、計画の内容、計画時の再確認でフォルダ消失を検出、日本語の文言。
- `tests/chat_ui.rs` `work_target_confirm_flow_fits_one_line_at_every_breakpoint_and_shows_errors`：ウィンドウを開かずにeguiの実際のウィジェットを操作する。360×480・900×480・1280×480のそれぞれで、入力欄をクリックしてパスを打ち、権限を選ぶ前の `確定` では確定しないこと、`読み書き` を選んで `確定` を押すと状態行が `作業対象: 確定済み: <パス> · 読み書き` になり、1行・ウィンドウ内・画面上に収まり、`\\?\` を表示しないこと、`計画（未実行）` とチャットの制限の行が出ることを確認する。360幅では長いパスが省略記号で切られることも確認する。続けて360幅で入力欄を全選択して存在しないパスに置き換えると確定が外れ、`確定` で `作業先が見つかりません` が出て、計画の行が消え、そのフォルダが作られないことを確認する。いずれの幅でもチャットの通信先へ何も届かない。
- `tests/chat_ui.rs` `confirmed_work_target_never_changes_how_the_chat_session_is_created`：同じ画面操作で、作業先を確定しない場合と `読み書き` で確定した場合のそれぞれで接続・送信し、メモリ内の模擬jcode peerが受けた要求列（権限要求への応答まで、Pingを除く）が一致することを確認する。セッション作成のフォルダは中立の `h2o-native-chat` 配下で作業先ではなく、system promptは `CHAT_SYSTEM_PROMPT`、ツールは空、権限要求は `Deny`。確定の操作だけでは接続先にも要求にも何も現れない。
- `tests/native_ui.rs` `display_path_drops_only_the_windows_verbatim_prefix`：`\\?\D:\…` と `\\?\UNC\…` の接頭辞だけを外し、通常のパスは変えない。

RED/GREENの記録（実行コマンド・exit code）は作業証拠 `target/swarm-run-stage5/evidence-T1.md`・`evidence-T2.md` にある。
