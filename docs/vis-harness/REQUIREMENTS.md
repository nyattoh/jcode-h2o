# ビス用ハーネス：要求仕様（実装途中）

状態: 研究用設計案。JCodeへの統合・GitHub上のfork・受付画面・実Jev連携は未完成。

## 目的

プロジェクトディレクトリを事前指定せずに受付botに相談し、必要に応じて複数botがJCodeのSwarmで協働する。H₂O Memoryの記憶管理と、Jevによる目的逸脱の監視・復帰・枝の打切りを組み合わせる。人の依頼と成果・履歴を追跡可能にする。

## 機能要求

1. 受付: 一般の会話と作業依頼を受け、対象が明らかになった時点で作業先を選択する。パス不明時に勝手に別プロジェクトへ書き込まない。UIはGrok Bot風の会話を基準とするが、参照画面の詳細は未確認。
2. bot: 識別子・役割・プロバイダ・能力・作業権限を設定で追加。受付のみを唯一の既定窓口とする。実際の起動・接続能力はadapterごとに確認し、不明は不明とする。
3. Swarm: JCodeの既存スケジューリングを利用し、目的、制約、所有範囲、変更結果を渡す。子の増殖と外部副作用の権限は明示する。
4. H₂O: 原文／正本と派生表現を区別し、使用中・待機・ディスク退避を扱う。原文を正確に戻せること。正本の訂正・削除・同意・履歴・実際のアクセス制御は本番に必要な別要件であり、現在の試作品にはない。
5. 目的監視: 目標・制約・成功条件と記録されたステップの関係を判定。目的に沿う／逸脱疑いへ分岐し、上限内で修正し、復帰しなければ当該枝を停止。元の目的や成果・根拠は保持。復帰回数は設定可能。通信エラー・不十分な証拠は保留とする。
6. Jev: JCode既存のJevClientを用いる候補。機密情報を外部へ送るため明示的な有効化、送信範囲の制御、失敗時の保留が必要。確率を真実や正確性の保証と扱わない。
7. 内部言語: エージェント間の文面は自然言語に限定しない。SemEvolveの言語版、run ID、原文、受領、理解確認、翻訳を区別し、エージェントが言語を提案・改訂できる。現在のSemEvolveは実験途上であり有効性は未証明。人向け表示時にのみ翻訳可能とする。
8. 計測: RSSとピークRSS、論理常駐量、ディスクI/O、レイテンシ、トークンと費用を別々に計測。取れない値はunknown。省エネや実環境改善を無測定で主張しない。

## 受入条件

- 再起動後にも正本を正確に取得でき、復元失敗や同一ID衝突を報告する。
- 枝の進行・修正・上限超過・Jev故障を独立に試験し、故障で枝を勝手に削除しない。
- 人が作業ディレクトリを入力せずに受付を開ける。実作業先と権限は実行前に確定する。
- 2 bot間で言語版付きの送受信と受領、理解確認、必要な人語訳を観測できる。
- 実JCode daemon、実Jev（有効化時）、実bot adapterで統合テストを行う。未接続なら未完成と表示する。
